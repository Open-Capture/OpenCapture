# Source code submission (Mozilla Add-on review)

This extension's build pipeline transpiles TypeScript, bundles multiple
files together (Vite/Rollup), and generates code from a compiled Rust/WASM
binary (`wasm-bindgen`) — so Mozilla's review process requires the actual
source alongside the submitted `.zip`, plus instructions to reproduce that
exact build. This document is that.

## What's source and what's generated

Everything in this repository **except** the following is hand-written
source, committed as-is:

| Path | What it is | Regenerated by |
|---|---|---|
| `apps/extension/dist/`, `dist-firefox/` | The built extension | `npm run build` / `build:firefox` |
| `apps/extension/src/wasm-gen/` | JS/TS glue generated from the compiled Rust core | `apps/extension/scripts/build-wasm.sh` |
| `apps/extension/vendor/{sdk,ui}/dist` | A pre-built copy of two internal packages, committed so `npm ci && npm run build` works without a separate build step | `apps/extension/scripts/build-vendor.sh`, from `vendor-src/` below |
| `apps/extension/vendor-src/{sdk,ui}/` | The **real TypeScript source** for those two packages | — this *is* the source |
| `target/`, `node_modules/` | Rust/npm dependency build caches | `cargo`/`npm` |

`@openapps/sdk` and `@openapps/ui` are first-party packages (part of the
same project family as OpenCapture, not an independent third-party
dependency), so their pre-built `vendor/{sdk,ui}/dist` doesn't stand in for
source on its own — `vendor-src/` is what does, and
`apps/extension/scripts/build-vendor.sh` is what proves `vendor/{sdk,ui}/dist`
is actually what that source produces, not something pasted in by hand.

`@openapps/tokens` (`apps/extension/vendor/tokens/`) is CSS and font files
only, with no build step — it's already source.

## Requirements

- **OS**: Linux or macOS. (Windows likely works under WSL; untested.)
- **Rust**: whatever `rustup` resolves from this repo's `rust-toolchain.toml`
  (currently the `stable` channel, plus the `wasm32-unknown-unknown` target
  and the `clippy`/`rustfmt` components) — install via
  [rustup.rs](https://rustup.rs); no manual version selection needed, `cargo`
  reads that file automatically.
- **`wasm-bindgen-cli` 0.2.100, exactly** — the crate and CLI versions are
  schema-coupled; a mismatch fails at build time with a clear error, not
  silently. Install: `cargo install wasm-bindgen-cli --version 0.2.100 --locked`.
- **Node.js 22+** and the `npm` that ships with it.

## Build

One script does everything, from a clean checkout to the exact
`apps/extension/dist-firefox/` this extension is submitted as:

```sh
./scripts/build-for-amo-review.sh
```

It: installs `wasm-bindgen-cli` if missing or wrong-versioned, rebuilds
`@openapps/sdk`/`@openapps/ui` from `vendor-src/` and refreshes
`vendor/{sdk,ui}/dist` from that build, installs the extension's own
dependencies, then runs `apps/extension`'s `build:firefox` (which itself
compiles `crates/shot-core` to `wasm32-unknown-unknown`, runs
`wasm-bindgen` to generate `apps/extension/src/wasm-gen/`, and bundles the
extension with Vite).

Output lands in `apps/extension/dist-firefox/`. What's submitted to AMO is
that directory, zipped:

```sh
cd apps/extension/dist-firefox && zip -r ../opencapture-firefox.zip .
```

## Manual step-by-step (equivalent to the script above)

```sh
cargo install wasm-bindgen-cli --version 0.2.100 --locked

cd apps/extension/vendor-src/sdk && npm install && npm run build && cd -
cp -R apps/extension/vendor-src/sdk/dist apps/extension/vendor/sdk/dist

cd apps/extension/vendor-src/ui && npm install && npm run build && cd -
cp -R apps/extension/vendor-src/ui/dist apps/extension/vendor/ui/dist

cd apps/extension
npm ci
npm run build:firefox
```
